## Git workflow

После каждого завершённого изменения кода (новая фича, исправление бага, рефакторинг) —
автоматически, **без запроса подтверждения**:

1. `git add .`
2. `git commit -m "<короткое сообщение по сути изменений>"`
3. `git push`

Делай это в конце каждой значимой единицы работы, не дожидаясь просьбы.

- Если коммит пустой (изменений нет) — молча пропусти эти шаги.
- Если push зафейлился (конфликт, отсутствие доступа) — **не форсить**. Сообщить, что
  произошло, и предложить решение.

### Важно: репозиторий на уровень выше

Git-репозиторий находится в родительской папке `budgeting app/`, а не здесь.
`git add .` из `budget-app/` заберёт только эту подпапку и пропустит остальное
(например `budget app plan/`). Поэтому команды выполнять из корня репозитория:

```bash
cd "/Users/illiachaikin/Documents/budgeting app" && git add . && git commit -m "…" && git push
```

Ветка `main`, remote `origin` → https://github.com/chayechka9/budget-app.git
Identity задана локально в репозитории; глобальный git-конфиг не трогать.

Сообщения коммитов — одна строка в императиве по-английски, по сути изменений
(«Add savings ring to Budget rows», а не «Update files»).
